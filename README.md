# Heart Symbol

A bilingual (English / Chinese) reflective journaling web app. You pick a topic and an emotion, draw one of twelve symbols, and receive a structured reading built to help you think — not to tell you what will happen.

## Why

Most "reflection" apps either give generic affirmations or lean on an LLM for everything, which makes them slow, inconsistent, and easy to get wrong in sensitive moments. Heart Symbol starts from a different assumption: the structure of a good reading — a mirror for how you feel, a grounded interpretation, a possible blind spot, a few honest questions, one realistic action — can be designed once, tested, and trusted. An optional AI layer can add a personalized narrative on top, but the app is complete and safe without it.

## How a reading is built

Every reading is generated by a **pure, deterministic engine** (`src/lib/readingEngine.ts`). Given a `(topic, emotion, symbol, locale)` input, it looks up:

1. **Emotional Mirror** — reflects the stated emotion back within the chosen topic
2. **Symbol Meaning** — the symbol's interpretation for that specific topic
3. **Possible Blind Spot** — a pattern worth noticing, keyed by emotion × symbol family
4. **Reflection Questions** — three fixed questions for the symbol drawn
5. **One Action for Today** — a realistic, non-prescriptive suggestion, selected deterministically so the same inputs always produce the same action within a session
6. **Closing Line** — a short sign-off keyed by topic

No network calls, no randomness, no side effects — every combination of inputs is covered and tested (`__tests__/lib/readingEngine.test.ts`).

## Optional AI personalization

Setting `GEMINI_API_KEY` unlocks a "Make it personal" step that asks Gemini to turn the deterministic reading into a more personal narrative. This layer is treated as untrusted by design:

- **Locale consistency check** — rejects responses that ignore the requested language (CJK-character heuristic in `aiNarrativeServer.ts`)
- **Prohibited-content filtering** — blocks future-certainty claims ("this will work out"), clinical diagnosis labels, guarantees, and fear-based escalation language before they ever reach the UI
- **Graceful fallback** — with no API key configured, the app works exactly the same, minus the personalize button

## Safety by design

A lightweight, client-side keyword scan (`src/lib/crisisDetection.ts`) checks free-text input in English and Chinese for high-risk language. If it matches, the UI surfaces a compassionate banner with a crisis helpline — **the user is never blocked from continuing**, and nothing is sent anywhere for this check. It's intentionally simple: the goal is surfacing a resource, not clinical classification.

## Tech stack

- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **Tailwind CSS 4** for styling
- **Vitest** + **Testing Library** for unit and component tests
- **Google Gemini** (`gemini-2.0-flash` by default) for the optional personalization layer

## Getting started

```bash
npm install
cp .env.local.example .env.local   # optional — add GEMINI_API_KEY to enable personalization
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

```bash
npm run test        # watch mode
npm run test:ci      # single run, for CI
npm run typecheck
npm run lint
```

## Project structure

```
src/
  app/              # routes: topic selection, drawing, reading, history
  components/       # UI components (layout, reading, symbol, ui)
  context/          # locale context
  data/             # symbols, emotional mirrors, blind spots, closing lines
  hooks/            # useAINarrative, useHistory, useLocale, useSession
  i18n/             # en/zh translation tables
  lib/              # reading engine, AI narrative client/server, crisis detection, storage
  types/            # shared TypeScript interfaces
__tests__/          # unit tests mirroring src/lib
```
